# Changelog

For the person bumping the submodule. Twenty projects vendor this, so anything
that moves pixels or changes an API says what you will see and what to do.
Started partway through the project's life, so it does not go all the way back.

## Unreleased

### Breaking

**The animation plugin is rewritten around `afterhours::motion`.** `animation::anim<Key>(k).to(v, dur, EasingType)`, `AnimationManager`, `AnimHandle`, `sequence`, `loop_sequence`, `one_shot`, `clamp_value`, `get_value`, `register_update_systems<Key>()` and the declarative `with_animation(Anim::on_hover()...)` / `HasAnimationState` are gone. Every old call is a compile error.
*What to do:* `motion::anim(key, entity.id)` (or `motion::anim(key)` for a value with no entity) returns a `Track<float>`; `.from(v).to(target, Spring::snappy())` for springs, `.to(target, Timeline{.keys = {{0,0},{0.3f,1}}, .curve = curves::ease_out_quad})` for a timed ease, `.then(...)` to chain, `.delay(s)`, `.value()` / `.value_or(d)` to read, `.active()` instead of `is_active`. `Spring::from_freq_decay(freq, decay)` reproduces the old ui spring numbers. Register once with `animation::register_update_systems(systems)` (no key type). Widgets use `.on_hover({.scale = 1.05f}, Spring::snappy())`, `.on_press`, `.on_focus`, `.on_appear({.opacity = {0.f, 1.f}})`, `.on_state(bool, ...)`, `.on_change(stamp, ...)`. `animation::set_instant` is unchanged. Tracks live on the entity (`motion::HasTracks`) and die with it; there is no `clear_all`.
*Why:* springs are solved in closed form so frame rate and stalls never change where a motion lands, retargeting keeps velocity, and hover/press/focus resolve to one target per property instead of fighting over a track.

**`HasScrollView::viewport_size` is now `std::optional`.** A plain `{0,0}` could not be told apart from a view genuinely measured as empty, so a consumer windowing its content read zero on frame one and silently built everything — which, before widget retirement, was a permanent plateau.
*What to do:* every read site is a compile error. `viewport_or_zero()` restores the old reading where you do not care; check `has_value()` where "not measured yet" is a real case, which it is for anything that windows.

**Labels lost their free 5px inset.** `Theme::text_inset` replaces a hardcoded 5 and defaults to **0**: edge-aligned text shifts, wrapped text re-breaks, auto-fit grows. Centred text does not move, so most screens are untouched — 97 of wm's 99 baselines were unaffected.
*Old pixels back:* build `-DAFTERHOURS_DEFAULT_TEXT_INSET=5.f`, verified pixel-identical. Per widget: `with_text_inset()`. Assigning a whole theme replaces it, so a screen swapping themes must re-state it.
*Also fixed by consolidating it:* the inset scales with `ui_scale` now (it was device pixels, so labels crept leading-ward on zoom), and `Dim::Text` charges it, so a box sized to its own text finally fits it.

**`Margin` field order now matches `Padding`** (`{top, left, bottom, right}`). Designated initializers and `Margin::Left(...)` are unaffected; a positional `Margin{a,b,c,d}` needs its middle two swapped and **will not error**, so grep for it.

**`colors::to_hsl`, `colors::to_rgb`, and `colors::get_highlighted` are deleted.** They had no callers, mixed 0-255 and 0-1 units so saturation came out wrong, and returned black with a warning on non-raylib builds.
*What to do:* use `colors::to_hsv` / `colors::from_hsv`. For `get_highlighted`, `colors::lighten` covers the same job.

### Visual — re-baseline

- **raylib falls back across loaded faces per codepoint, like sokol.** A glyph the label's face lacks is now drawn from the first other face loaded through `load_font_*` that has it, instead of the replacement glyph. `measure_text` sums the same runs `draw_text_ex` places. The replacement is used only when no loaded face covers the codepoint. Load order is priority. Known limits: rotated text and text containing `\n` use the primary face only, and fallback glyphs sit on their own face's ascent rather than the primary's baseline. `fallback_runs(font, text)` shows the split. Covered by `raylib_fallback_test`.
- **A codepoint no loaded face covers draws a visible replacement.** It used to draw nothing on raylib (a blank glyph) and the face's `.notdef` on sokol. Now it draws U+FFFD when a face has it, otherwise `?`, and `measure_text` measures that same replacement. A ZWJ emoji sequence or a flag becomes one replacement, and uncovered variation selectors and skin-tone modifiers vanish. U+FFFD joins `default_codepoints()` so raylib loads it when the face has it. Labels with uncovered symbols change pixels and width; load a face that covers them. `drawable_text(font, text, storage)` returns what will be drawn, and `font_coverage::visible_text` is the rule. Covered by `glyph_placeholder_test` and `headless_fallback_test`.
- **`colors::UI_RED`, `UI_GREEN`, `UI_BLUE` are raylib's red, green and blue on every backend.** They were raylib's values on raylib but pure 255 primaries on sokol and none, so the same name drew two colors. raylib builds are unchanged. On sokol (wordproc, floatinghotel), anything drawn with them shifts to raylib's shade. Want the pure primary? Use `colors::rgb(255, 0, 0)`. `UI_WHITE` and `UI_PINK` still differ per backend.
- **A child overflowing the cross axis is aligned, not dumped at the start.** `AlignItems::Center`/`FlexEnd` used to silently fall back to `FlexStart`; centring now overflows both edges evenly, per CSS. Moved 10 of 98 screens in wm.
- **Scroll-view children are laid out by autolayout** instead of repositioned afterwards by two drifted copies that double-counted margins. Margined direct children move by one margin, into the right place, and keep the `justify`/`align`/`gap` the old pass discarded.
- **Cross-axis `expand()` stretches** instead of collapsing to 0, so separators and fills that were invisible now have a size.
- **Scroll views draw a draggable scrollbar** on the overflowing edge of each enabled axis. `show_scrollbar = false` opts out; `scrollbar_thickness`/`scrollbar_min_thumb` are h720 Sizes so the bar tracks the window.
- **Left-aligned menu labels sit one row pad in from the edge**, matching the shortcut on the other side. They were flush, and a focus ring stroked over the first glyph. Rows also take `with_padding`, a theme usage from `with_background(Usage)` and `with_custom_hover_bg` from the menu's config; before, only a custom colour reached them. Padding also moves the label inset and the shortcut/mark offsets, so they stay lined up. Menus with marks keep their mark column. Covered in `menu_test`; `examples/catalog/ui/menu_styling`.
- **Under grid snapping, `children()` sizes and scroll extents match where children are placed.** Placement snaps the running offset after each child, so 28px rows with a 6px gap land every 36px at 1080p. A `children()` column summed 28 + 6 per row and came out 10px short (wm's profiler rows), and a scroll view summed 22.5px rows that were placed every 25px, so the last lines could not be scrolled to (floatinghotel). Both now follow the snapped positions, so `children()` containers with off-grid rows or gaps grow by a few pixels. Nothing changes with snapping off or with on-grid sizes. Covered in `sizing_repro_test`; `examples/catalog/ui/grid_snap_extents`.
- **Menu shortcuts sit one pad in from the panel edge** — they were flush, clipping the last glyph in half.
- **Labels clip to their own box.** A label used to paint past its element on every side, and a wrapped label whose lines outgrew the box spilled the extra lines over whatever was below. Text is scissored to the element's box now, and a wrapped line that does not fit is dropped. Screens whose labels relied on the spill change; give the label the height or the ellipsis instead.

### New APIs
- **Chamfered corners.** `RoundedCorners().chamfer(CornerPosition)` (plus `chamfer_left()` / `all_chamfer()`) and `with_chamfer_corners(bitset)` cut a corner at a straight 45 degrees instead of arcing it, sized by the same `roundness` / `with_corner_radius` as rounded corners and honoured per corner in both renderers (fill, outline, border, shadow, focus ring). A chamfered corner needs no rounded bit; where both are set, the chamfer wins. Sharp is neither bit (unchanged). cartographer hand-drew 3px-cut tab corners because there was no clip-path or chamfer. Covered by `chamfer_corners_test` (raylib) and `sokol_chamfer_corners_test` (sokol).
- **`with_takes_focus(false)`** lets an element be clicked or dragged without moving keyboard focus to it, so a disclosure clicked while typing leaves the caret in the composer. Hover-follow focus (`FollowsMostRecentInput`) also skips it. It stays in Tab order, so keyboard users can still reach it and press it. hanabi refocused its composer a frame after every such click, which flashed the ring onto the clicked element. Covered in `hit_priority_test`; example `examples/catalog/ui/click_without_focus`.
- **`with_inert(bool = true)`** makes an element and everything inside it ignore the pointer and keyboard focus, while it still draws. Use it on a menu that is fading out or a panel animating away, so a click on a button that is disappearing does nothing. It is checked up the parent chain, so one flag on the panel covers every button in it. cartographer had nothing for this: elements at opacity 0 still took clicks and focus. It is explicit rather than tied to opacity because invisible hit areas are a real pattern (cartographer's desk uses them). Covered by `inert_test`; example `examples/catalog/ui/inert_fade`.
- **`Theme::focus_ring_contrast`** (default `true`, so nothing changes) turns off the black/white hairlines drawn just outside and just inside the focus ring, in both renderers. With it off, a 1px ring is one 1px line. Before, it measured as a 3px white-blue-white band whose edges took their colour from the ring rather than from what it sits on. `FocusRing::contrast_edges` carries the setting to custom widgets that draw their own ring from `focus_ring_for`. Covered in `downstream_gaps_test`; `examples/catalog/ui/focus_ring_single_outline`.
- **`graphics::Config::audio` and `RunConfig::audio`** (default false) open the audio device for the session. On raylib, `graphics::init` (and so `ui::run`) and `graphics::run` call `InitAudioDevice` after the window or headless context comes up, and `shutdown` / the end of `run` close it again. Apps that play sound no longer need to bracket `main` by hand (voice_ah). If no device can be opened, it's a warning and the app carries on silent. The sokol backend has no audio device yet, so it warns that the flag is ignored. Covered by `audio_lifecycle_test`; `examples/catalog/utility/audio_in_run`.
- **`local_time_now()` / `to_local_time(time_point)`** (`src/local_time.h`, std only, every backend) return the wall-clock local date and time as `SerializableLocalDateTime` (`year`, `month` 1-12, `day`, `weekday` 0=Sun, `hour`, `minute`, `second`), or `nullopt` if the platform can't convert. They use `localtime_r` / `localtime_s`, so they're thread-safe. `weekday_name()` and `month_name()` give English short names (`"Sat"`, `"Nov"`) whatever the locale. `get_time()` is still elapsed time. pumpkin-beachball's desktop-themed menu bar carried its own `std::localtime` call and day/month tables for this. Covered by `local_time_test`; `examples/catalog/utility/local_clock`.
- **`load_font_from_memory(data, size, name)`** on every backend loads a font from bytes, for example a TTF embedded in the binary. Coverage is recorded from the same bytes, so `font_has_glyph` works. On sokol the bytes are copied, so the caller's buffer can go away, and loading the same `name` or file path again returns the already-loaded face instead of reading and parsing it again (`load_font_from_file` used to reread the file on every call). raylib takes an optional pixel size like `load_font_from_file`. NONE returns an empty font. Covered by `font_memory_test` (sokol) and `headless_fallback_test` (raylib).
- **`font_coverage::font_size_per_point(path)`** (`src/font_coverage.h`, any backend) returns the factor that turns a CoreText or CSS point size into an afterhours font size for that face, or `nullopt` if the file is unreadable. Both backends size text by line height (hhea ascent minus descent), while points size the em, so 13pt Atkinson Hyperlegible is font size 16.12, not 13. Multiply your point tokens by the factor once per face. A bytes overload exists for fonts already in memory. hanabi's `type::set_point_scale` and floatinghotel's hand-calibrated sizes can use it. Covered by `font_points_test`, which checks the factor against stb_truetype's em scale for both fixture faces.
- **`files::TestRoots`** (`src/plugins/files.h`) points save, config and temp at a fresh `afterhours-test-*` directory under the system temp dir for its lifetime, then restores the previous paths and deletes the directory. Create it before `files::init()` and the real save folder is never created; an already-initialized provider is redirected and put back. The settings plugin follows because it resolves against the files save path, unless the app set `settings::set_path_override`. Scopes nest and must end in reverse order (out of order aborts). Use `roots.temp` for scratch files. floatinghotel and MyNameChef were redirecting each field by hand and still leaking into the real save root. Covered by `files_test_roots_test`.
- **Text editing and click-to-caret step by grapheme cluster.** Left/Right, Backspace and Delete in `text_input` and `text_area`, and click or drag placement (`offset_nearest_x`, `pixel_x_to_byte_offset`), used to step one codepoint at a time. One Backspace left `👩🏽‍` behind from `👩🏽‍💻`, and a click could put the caret between a flag's two halves. `ui::next_grapheme_end(text, i)` and `ui::prev_grapheme_start(text, pos)` (`src/plugins/ui/text_units.h`) are the cluster rule `split_graphemes` already used: combining marks, variation selectors, skin tones, ZWJ sequences and flag pairs. Not covered: Hangul jamo sequences, Indic spacing marks, CRLF as one cluster. Covered by `grapheme_edit_test`.
- **`ui::ellipsize_text(text, max_width, width, ellipsis = "...")` and `ui::fit_text_prefix(text, max_width, width)`** (`src/plugins/ui/text_units.h`). `width` is any `float(const std::string &)`, so a raw-draw game passes a lambda over `measure_text(font, ...)` and a UI app passes one over its theme's measure. `fit_text_prefix` answers how many bytes fit; both cut only on grapheme boundaries and binary-search, so a row costs O(log n) measures. The renderer's `TextOverflow::Ellipsis` now calls the same helper, so its two copies are gone and it no longer cuts inside a multibyte character or emoji. pumpkin-beachball's `ellipsize_text` and hanabi's `fit_to_width` can be deleted. Covered by `text_fit_test`.
- **`UIContext::grab_initial_focus`** (default `true`). Set it to `false` and nothing is focused when a screen loads or after the focused element goes away. The first Tab, or Down when `arrows_tab` is on, focuses the first focusable element and counts as interaction, so the ring shows. cartographer's menus otherwise opened with the first button focused, so Enter activated it before the player had chosen anything. To focus a particular element first, call `set_focus` on it the frame it is built. Covered in `focus_origin_test`; example `examples/catalog/ui/no_initial_focus`.
- **`TreeViewConfig::render_row(Entity &row, const T &, const TreeRowInfo &)`** (`ui/tree_view.h`) builds a tree row's contents in place of the default `"> " + label`. `TreeRowInfo` carries `depth`, `expandable`, `expanded` and `selected`. The row is still the tree's button, so click-to-select, expand/collapse and the indent padding stay native. The callback adds children to `row` (capture your context) for disclosure marks, icons, guides or a size column. wm's FileTreeShowcase walked the tree's descendants after the build to do this. Unset, rows are unchanged. Covered in `tree_view_test`; `examples/catalog/ui/tree_view_rows`.
- **`Vector4Type`, `MatrixType`, `graphics::Camera2D`.** Two more host type macros: `raylib::Vector4` / `raylib::Matrix` on raylib, plain structs elsewhere. The struct `MatrixType` uses raylib's field names and order (`m0, m4, m8, m12, m1, ...`), so code that reads `m.m12` ports unchanged. `MatrixType` was only reachable through `plugins/models.h` before. `graphics::Camera2D` names `PlatformAPI::Camera2D`. Replaces the `typedef raylib::Vector4 vec4` 12 projects copied from the template.
- **`FrameRateStats`** (`src/frame_rate_stats.h`, std only) averages frame rate over a window. Call `add(dt)` once a frame; it returns true each time a window (default 1s) completes, and then `fps()`, `avg_frame_ms()` and `max_frame_ms()` describe that window. `graphics::get_fps()` is instantaneous, and `plugins/profiling.h` is an opt-in per-system profiler, so pumpkin-beachball wrote its own trailing-window logger. You choose the clock by choosing the dt: pass the fixed E2E step and the HUD number is deterministic in screenshots. Covered by `frame_rate_stats_test`; `examples/catalog/utility/frame_rate_stats`.
- **raylib's color names on every backend.** `colors::RED`, `colors::SKYBLUE`, `colors::RAYWHITE` and the other 23 raylib palette names, with raylib's exact values. On raylib they are raylib's own macros, so `colors::RED` and bare `RED` are the same color everywhere. Code ported to sokol can keep its palette.
- **`files::get_cache_path()`** (and `ProvidesResourcePaths::get_cache_path()`) is a per-app directory for data you can regenerate: `~/Library/Caches/<game>` on macOS, `$XDG_CACHE_HOME/<game>` (default `~/.cache`) on Linux, and the local app-data folder on Windows (from `sago::getCacheDir()`), or `/cache/<game>` on Emscripten. Separate from `get_config_path()`, so a cache can be cleared without touching settings. Natively it isn't created until you call `files::ensure_directory_exists`, the same as config. Covered by `files_cache_path_test`; `examples/catalog/plugins/cache_dir`.
- **`input::is_held(Action)` / `input::is_pressed(Action)`** take your own action enum and answer for any gamepad, reading `inputs()` and `inputs_pressed()` from the collector. Both return false before the input plugin exists. `input::add_singleton_components(entity, std::map<Action, ValidInputs>)` takes an enum-keyed mapping, so no `to_int` casts are needed. tetr kept a `held_actions()` scan plus `to_int` / `from_int` helpers for this. Covered by `input_enum_actions_test`; example `examples/catalog/plugins/enum_actions`.
- **raylib one-liners on every backend.** `draw_fps(x, y)`, `graphics::get_key_pressed()` (a per-frame queue, 0 when empty, like `GetKeyPressed`), `unload_font(font)`, `keys::NULL_KEY`, and `set_texture_wrap(tex, TEXTURE_WRAP_REPEAT | _CLAMP | _MIRROR_REPEAT)`. On sokol, `set_texture_filter` now keeps the wrap, and `unload_font` only clears the handle because fontstash cannot free one face. none: no-ops. `TEXTURE_FILTER_TRILINEAR` already existed.
- **`RngStream`** (`src/random_engine.h`) is a seeded generator you own, so several can run side by side: a shop stream and a battle stream, or one per world, with no shared state. It has the same `get_int` / `get_float` / `get_bool` / `get_index` as `RandomEngine`. `save()` returns the seed plus the full consumed state as a string. `RngStream::load(text)` resumes it exactly, or returns `nullopt` with a warning for anything else. A stream can be passed straight to `EntityQuery::gen_random(stream)`. `RandomEngine` is unchanged and now holds one, exposed as `stream()`, so the global can be saved too. Sampling uses the standard library's distributions, so two different standard libraries can still disagree on values. Covered in `random_engine_test`; `examples/catalog/utility/rng_streams`.
- **Host type macros are documented.** README "Host type macros" lists the six macros (`Vector2Type`, `Vector3Type`, `RectangleType`, `ColorType`, `FontType`, `TextureType`), their per-backend defaults, the fields afterhours reads, and that they must be defined before the first afterhours include. Example: `examples/catalog/utility/host_types`.
- **`input::Repeat{delay, rate}`** paces a held input. `tick(held, dt)` returns how many times to act this frame: 1 on the press frame, then one each `rate` seconds once `delay` has passed. The remainder carries between frames, so a one-second hold fires the same count at 60 and 200 fps, and a long frame returns several. It takes any held bool, so keys, gamepad buttons and axes all work. tetr gated Move, Rotate and Drop with its own `RepeatGate` timers, which could hold back a fresh press by up to one period. Covered by `input_repeat_test`; example `examples/catalog/plugins/input_repeat`.
- **`SystemManager::fixed_tick_rate` and `max_fixed_ticks`** (`src/core/system.h`). The fixed-update step was the constant `FIXED_TICK_RATE` (1/120), with no limit on catch-up, so a 2s hitch ran 240 fixed updates in one frame. `fixed_tick_rate` defaults to that constant and `max_fixed_ticks` defaults to 0 (no cap), so nothing changes until you set them. With a cap, extra time past it is dropped rather than carried over. A rate of 0 or less fails a `VALIDATE`. Covered by `fixed_tick_rate_test`; `examples/catalog/core/fixed_tick_rate`.
- **`ui::monospace_cell_advance(font_name, font_size)`** (`src/plugins/ui/text_measure.h`) returns one monospace cell's advance, derived from the digit glyph the backend actually exposes: raylib reads `GlyphInfo.advanceX` for `0` (rect width when that is zero, estimate when there is no atlas), sokol takes `fonsTextAdvance` for `0`, and the none backend goes through its measure seam. It bypasses `TextMeasureCache`, so a line-number gutter is `digits * advance` instead of measuring a fresh space string per distinct row count and filling the cache with them. Invalid sizes and a missing `FontManager` return 0. Covered by `monospace_cell_test`, plus cell checks in `font_atlas_measure_test` (sokol) and `headless_fallback_test` (raylib).
- **`FontManager::load_font_with_codepoints` takes a load size.** `load_font_with_codepoints(name, file, codepoints, count, size = 32)` rasterizes the atlas at `size` on raylib, so a face loaded for large display text is no longer stuck at the old hidden 32px. Omitting `size` loads at 32px exactly as before. On sokol the size is accepted and ignored: fontstash loads the full face and rasterizes at draw size, and codepoints are likewise unused there; on the none backend it is accepted and ignored. Covered by `load_font_size_test`.
- **`ctx.is_middle_click(id)`** and `MousePointerState::middle_down` / `middle_just_pressed` / `middle_just_released`. It is true on the release frame when the pointer was over `id` or something inside it, the same way `is_right_click` works, so a tab can close on middle click. On raylib, e2e builds now route `is_mouse_button_down(2)` to the injector, so `middle_click` scripts reach the UI. hanabi polled button 2 itself and redid the tab strip's hit math. Covered by `middle_click_test`; example `examples/catalog/ui/middle_click_close`.
- **CPU images and pixel upload** (`src/image.h`, include it directly; every backend). `image_size(bytes)` / `image_size(path)` read dimensions from the header without decoding or touching the GPU. `decode_image(bytes, ImageLimits{.max_dimension, .max_bytes})` / `load_image(path, limits)` return an `Image` with owned RGBA8 `rgba` and `pixel(x, y)`; dimensions are checked against the limits before anything is allocated, and bad input returns `nullopt` with a warning. `load_texture_from_rgba(rgba, w, h, filter)` uploads pixels on raylib and sokol (call it on the render thread); `none` returns an empty texture. floatinghotel and hanabi can drop `metal_texture_detail::load_texture_from_pixels`, cartographer's `LoadImage`/`GetImageColor`/`UnloadImage` triples become one `load_image`, and pumpkin-beachball's `sprite_aspect` table can come from `image_size`. raylib and sokol already link stb_image; a `none` build defines `AFTERHOURS_STB_IMAGE_IMPLEMENTATION` in one TU before including `image.h`. Covered by `image_test`, `image_raylib_test` and `image_metal_test`.
- **Wrapped lines as byte ranges: `ui::wrap_text_lines(text, max_width, font, size)` / `detail::wrap_lines(text, max_width, measure)`** (`src/plugins/ui/text_selection.h`, `text_measure.h`). Each `WrappedLine` is `{begin, end, width}`: byte offsets into `text` and the line's measured width, so line counts, find-highlight and selection index the source without re-finding each line or re-measuring it. The space a soft wrap consumes and the `'\n'` of a hard break fall between ranges. `wrap_text`, `wrap_text_to_width`, `measure_wrapped` and the styled `wrap_runs_to_width` now all slice one range pass (`detail::wrap_ranges`), so their breaks are unchanged and cannot drift apart; a 20,000-case diff against the old code matched exactly. `TextLayoutCache` uses it instead of `find`-ing each line in the source. Covered by `text_wrap_test`.
- **`ComponentConfig::with_virtual_list_overscan(n)`** sets how many rows a `virtual_list` builds past each edge of its viewport. It defaults to 4, so existing lists build exactly what they built before; `with_virtual_list_overscan(0)` builds only the visible rows and a larger value trades more row entities for fewer blank frames on fast scrolls. Covered by `virtual_list_test`.
- **`parse_e2e_args` accepts `--key=value` spellings and `--e2e-timeout`.** Every value-taking e2e harness flag (`--test-script`, `--test-script-dir`, `--screenshot-dir`, `--timeout`, `--slow-delay`, `--time-scale`, `--e2e-speed`, `--capture-interval`) now parses in `--key=value` form as well as the separated `--key value` form, and `--e2e-timeout` is an alias of `--timeout` in both forms. `should_run_e2e` recognises the `=` spellings of `--test-script`/`--test-script-dir` too. Separated spellings and unknown-argument handling are unchanged. Covered by `harness_spellings_test`.
- **Runtime remapping for the non-layered input map** (`src/plugins/input_system.h`). `input::ProvidesInputMapping` now has `set_binding(action, inputs)` and `clear_binding(action)`, matching `ProvidesLayeredInputMapping`, plus `actions_using(binding)` on both maps (and `input::actions_using(mapping, binding)`) to find conflicts before rebinding. `KeyChord`, `GamepadButton`, `GamepadAxisWithDir` and `MouseAxisWithDir` gained equality so bindings can be compared. Covered by `input_remap_test`.
- **Sound playback and device wrappers** (`plugins/audio_helpers.h`): `StopSound`, `PauseSound`, `ResumeSound`, `SetSoundPitch`, `SetSoundPan`, `IsMusicStreamPlaying`, `IsAudioDeviceReady`, `SetMasterVolume` / `GetMasterVolume` and `SetAudioStreamBufferSizeDefault`, next to `PlaySound`. voice_ah (stopping a line on Skip), mailboy (pitch per note) and the 11 projects in the raylib usage audit called raylib directly for these. They forward to raylib. Other backends get no-op stubs, and `IsAudioDeviceReady()` returns false there. `SetMasterVolume` is the device's volume, separate from `sound_system`'s own master multiplier. Call them qualified (`afterhours::StopSound(s)`): with a `raylib::Sound` argument, an unqualified call also finds `raylib::StopSound` through argument-dependent lookup and is ambiguous, the same as the existing wrappers. Covered by `sound_playback_test`; `examples/catalog/utility/sound_controls`.
- **`text_input::edit_command_from_keys()`** (`src/plugins/ui/text_input/edit_keys.h`) returns this frame's `EditCommand` from the platform's text-editing chords: the same ones `default_keymap` binds, with modifiers matched exactly, so Cmd+Shift+Z is Redo and not also Undo. A field the app draws itself can call `apply_edit_command` on its own `HasTextInputState` without Text* names in its enum. Define **`AFTERHOURS_NO_IMM_TEXT_INPUT`** to silence the start-up warning about missing Text* names in an app with no imm text input. Covered by `edit_keys_test`.
- **`InstanceBatcher` groups by a key and runs a hook per group.** `add(model, transform, key)` (and the pos/yaw/scale form) splits one model's copies into groups by a `uint32_t` key, e.g. in fog or not and wind sway on or off; the key defaults to 0, so existing calls are unchanged. `flush(shader, on_group)` calls `on_group(model, key, std::span<const MatrixType> transforms)` before each group draws, to set that group's uniforms or to feed the same transforms to a shadow pass. Group lookup is a hash map now rather than a linear scan, so scenes with hundreds of distinct models stay O(1) per `add`. Draw order is still first-seen. Covered in `instance_batcher_test`.
- **`set_default_font(font)` / `clear_default_font()`** (every backend). The face for text drawn without one: `get_default_font()`, `get_unset_font()`, `draw_text`, and the UI plugin's default and unset fonts when it is set before the plugin loads them, so debug panels and charts stop falling back to raylib's tiny pixel font. Unset, nothing changes. The caller keeps the font loaded. Covered by `default_font_test`.
- **`InstanceBatcher` and `model_transform`** (`src/plugins/models.h`, raylib). Walk the entities calling `batcher.add(model, pos, yaw_deg, scale)` (or `add(model, matrix)`), then `batcher.flush(load_instancing_shader())` once a frame: copies group by model and each group draws with one `draw_model_instanced`. `flush` keeps the storage, so a steady scene stops allocating after its first frame. Groups key on the model's address, which `ModelLibrary` keeps stable; copies needing another shader or uniforms go in a second batcher. `model_transform(pos, yaw_deg, scale)` is the matrix `draw_model` builds, for filling instanced draws without raymath. cartographer carries the same batching as `DrawBatch` in `RenderCollidablesSystem`. Covered by `instance_batcher_test`, which renders a batched frame and the same scene with `draw_model` per copy and finds them pixel-identical.
- **`Lod`: level of detail from distance without flicker** (`src/plugins/lod.h`, every backend). Keep one per copy; `lod.update(distance, {25.f, 60.f})` returns 0, 1 or 2. A copy moves out a level only once it is `margin` (default 0.15) past a threshold and back only once it is `margin` inside, so one hovering on the line holds its level. Thresholds can change between calls; a level past the new end clamps. cartographer writes this by hand per system (`lod_high` with 25m in / 35m out = threshold 30, margin about 0.17). Covered by `lod_test`.
- **`Lod::update_sq(distance_sq, thresholds, margin)`** for loops that already have squared distance (culling usually does). Thresholds stay linear and are squared inside, so there is no `sqrt` per copy; levels match `update` exactly. Covered by `lod_test`.
- **View frustum culling** (`src/plugins/frustum.h`, every backend): `make_frustum(camera, aspect)` builds the six planes from a `Camera3D` directly, perspective or orthographic, with raylib's near/far by default. `contains_point`, `intersects_sphere`, `intersects_box` (axis-aligned, e.g. a model's bounding box). The sphere and box tests are conservative: something just outside a corner can report visible, nothing visible reports hidden. cartographer carries the same thing as `FrustumPlanes` in `systems/frame_cache.h`. `frustum_test` checks it against raylib's own projection matrices on 60,000 random points across 200 random cameras.
- **`make_frustum(view_projection)`** builds the planes from a combined view * projection matrix (Gribb-Hartmann, normalised), for passes whose projection is not a plain camera: a shadow pass with its own clip planes, a picture-in-picture with its own aspect. Call it inside the pass with `MatrixMultiply(rlGetMatrixModelview(), rlGetMatrixProjection())`. Takes any type with raylib's `m0..m15` fields. cartographer carries this as `FrustumPlanes::extract`. Checked in `frustum_test` on the same 60,000 points.
- **Lit, fogged models and cards** (`src/plugins/models.h`, raylib, desktop GL). `load_lit_shader(lighting = DEFAULT_LIGHTING)` lights a model per pixel; put it on with `set_model_shader`. `lighting` is a GLSL snippet defining `vec3 lighting(vec3 albedo, vec3 world_pos, vec3 world_normal)`, with `camPos` declared for it. `DEFAULT_LIGHTING` is one directional light, ambient, and linear distance fog. Write your own (point lights, height fog, a toon ramp) and pass the same snippet to `house_of_cards::load_shader` so cards shade the way models do. Their normals are baked per view and blended like the colour. `apply_lighting(shader, Lighting{...}, camera_pos)` sets the default's uniforms; fog stays off while `fog_far <= fog_near`. Lit cards come within 1-5% mean colour error of the lit model (`hoc_compare --lit`). Flat-shaded low-poly models land at the high end because blending views softens their faces. `examples/catalog/3d/house_of_cards` toggles lighting with L and fog with F.
- **house_of_cards impostor cards** (`src/plugins/house_of_cards.h`, include it directly; raylib, desktop GL). Based on Thomas R Murphy's Imposter Cards add-on ([Superhive](https://superhivemarket.com/products/imposter-cards-nacho-time), [BCON26 talk](https://www.youtube.com/watch?v=qBPuZ-1StZc)), with the octahedral view layout from Ryan Brucks' impostors. `bake(model)` renders the model from 16x16 directions over the sphere into colour, depth and normal atlases (64px per view, 1024px total). `save` / `load` handle `<prefix>.png`, `_depth.png`, `_normal.png` and `.cards`; a bake missing any of them fails to load. `draw_instanced(cards, load_shader(), transforms, n, camera)` draws every copy as one quad facing the camera: the shader casts the eye ray into the three nearest views, refines with their depth, and blends. The add-on's six axis views were tried and dropped: they scored lower on every example and needed a depth march costing about 4x per pixel. Lit cards: pass the same lighting snippet to `load_shader(DEFAULT_LIGHTING)` and to `load_lit_shader()` for the real models, and they shade alike (see the next entry). `load_shader()` with no argument stays unlit. Covered by `house_of_cards_test`, which also lights cards and model from two opposite sides and checks they still agree.
- **3D models** (`src/plugins/models.h`, include it directly): `ModelLibrary::get().load(path, name)` returns false and stores nothing when the file does not load. raylib returns an empty model instead of failing, so `Library::load` used to store that model and report success. `get` / `contains` / `unload_all` match the sound libraries, and `unload_all` also drops the entries so a later `get` fails instead of returning freed GPU data. `draw_model(model, pos, yaw_deg, scale, tint)` draws about Y with pure white as the default tint (`colors::UI_WHITE` is RAYWHITE under raylib and darkens models). `set_model_shader(model, shader)` sets every material's shader; the caller still owns the shader. `is_model_loaded` is the empty-model check. `draw_model_instanced(model, shader, transforms, count)` draws every copy with one `DrawMeshInstanced` per mesh and leaves the model unmodified; `load_instancing_shader()` is the unlit shader it needs, since raylib's default shader has no per-instance transform (GLSL 330, desktop only; the caller unloads it). Examples in `examples/catalog/3d/` (`model_loading`, and `model_stress` with a `--bench` ramp); covered by `models_test`.

### Fixes
- **raylib fonts loaded headless draw again, and drawing a textureless font never segfaults.** #105 made the file loaders skip `build_font_atlas` when `IsWindowReady()` is false, but the headless backend has a GL context without a window, so every font loaded there came back textureless and `DrawTextEx` segfaulted on it (wm_afterhours menu_showcase). The loaders now build the atlas when a GL context is actually ready (window, or the headless `isGpuReady` flag), and `draw_text_ex` draws nothing for a font with no atlas instead of calling into raylib. Covered by `headless_fallback_test`.
- **Up and Down stay in a focused `text_input` or `text_area`.** With `Theme::arrows_tab` on (the default), arrows move focus unless the focused element has `ConsumesDirectionalInput`, and the widgets' focusable field child did not have it. Down in a search box therefore left the box and selected the row below. Both widgets now mark their field. Tab still moves focus as before. floatinghotel marked the focused field itself every frame. Covered in `text_input_test` and `text_area_test`; example `examples/catalog/ui/field_arrows`.
- **`slider` and `toggle_switch` follow the value you pass.** Both seeded their retained state once and wrote it back over the caller's value every build, so a reset or tab switch that wrote `float&`/`bool&` from outside was undone the next frame. They read the caller's value each build now, as `checkbox` and `stepper` already did; a drag, arrow key or click not yet read still wins. If you hand-wrote `HasSliderState::value` or `HasToggleSwitchState::on` to work around it, delete that. `color_swatch` dropped its own copy of the workaround. Covered in `slider_test` and `checkbox_mark_test`; `examples/catalog/ui/controlled_widgets`.
- **`set_focus` on the entity `text_input` or `text_area` returns focuses the field.** The returned entity is a wrapper; the focusable field is its child, so `EndUIContextManager` dropped wrapper focus at the end of the frame and the first focusable widget took it. hanabi and floatinghotel reached into `children[0]` and re-asserted focus over several frames. The wrapper now carries `FocusProxy{field}` and `UIContext::set_focus` follows it, including on the frame the widget is first built. Any composite can add `FocusProxy` the same way. Covered in `text_input_test` and `text_area_test`; example `examples/catalog/ui/focus_text_input`.
- **`with_overlay` survives `apply_overrides`.** `render_layer_offset` was never merged, so an override that asked for an overlay came out absolute but on its parent's layer. `config_size_test` also expects 1544 now, the size after `focus_ring_thickness` (already merged). Covered in `overlay_layer_test`.
- **An automatic focus grab no longer changes `focus_modality`.** When the focused element went away, `try_to_grab` refocused the first widget with `FocusSource::Grab` and recorded Grab as the modality, so anything showing a ring for "not pointer" lit it up with no user input. A Grab now keeps the previous modality. cartographer's desk ignored Grab focus to work around it. Covered in `focus_origin_test`.
- **raylib `load_font_from_file` and `load_font_from_file_with_codepoints` no longer segfault without a window.** When `LoadFontEx` returned no texture they called `build_font_atlas`, whose `LoadTextureFromImage` goes through a null GL function pointer before `InitWindow`. They now check `IsWindowReady()` first, as `load_font_for_string` already did, and return the glyphs with no texture. Covered by `headless_fallback_test`.
- **Drag groups hit-test where a scrolled strip is drawn.** Drag start, drop-group hover and the insertion index used raw layout rects, so after an ancestor scrolled, a press picked the item that used to be under the pointer and an item scrolled out of view could still be grabbed. They go through the same scroll transform and viewport clip as ordinary hit testing now. hanabi computed tab drop slots itself and wm_afterhours translated page indices to work around it. Covered by `drag_scroll_hit_test`; example `examples/catalog/ui/drag_scrolled_strip`.
- **`crash::install_handler()` no longer recurses in a host whose `log_error` aborts.** The report went through `log_error`. Under `AFTER_HOURS_REPLACE_LOGGING` with an asserting `log_error` (endless-dance-chaos), that meant signal, report, abort, SIGABRT, the same handler, and so on, so the app had to leave the handler uninstalled. The report now writes `[ERROR] ...` lines to stderr and `log_sink_fn` directly, which is what built-in logging already did, so `log_file.h` still captures it. A crash inside the report no longer starts a second one. A host that replaced logging no longer sees crash lines in its own `log_error`; they go to stderr and the sink. Covered by `crash_handler_reentry_test`; `examples/catalog/utility/crash_report_strict_host`.
- **`with_disabled(true)` blocks clicks on controls without their own label.** Hit testing, `HandleClicks`, tray navigation and the touch-target validator read disabled state only from `HasLabel`, so a card or row whose text lives in child labels stayed clickable while disabled. `with_disabled` now also adds an `IsDisabled` marker, and those four sites ask `ui::is_disabled(entity)`, which checks either one. wm_afterhours removed the listener from unavailable actions to get the same effect. Covered in `hit_priority_test`; example `examples/catalog/ui/disabled_card`.
- **`Dim::Text` measures the face and spacing the renderer draws.** Autolayout measured a label with its base `font_name` and spacing 1, while both renderers draw the `with_font_weight` variant (`resolve_weighted`) with `1 + letter_spacing`. So a bold or letter-spaced label sized to its text came out too narrow and clipped or ellipsized. Autolayout now resolves the weight and adds the label's letter spacing. Labels using either one change width. Covered in `autolayout_test`.
- **Ctrl+Shift+Z no longer also fires the Ctrl+Z action.** Explicit chords accept extra modifiers, so pressing Ctrl+Shift+Z matched both an Undo bound to Ctrl+Z and a Redo bound to Ctrl+Shift+Z, and the collector reported both. When two explicit chords match the same key now, the one whose modifiers are a subset of the other's is dropped, so the more specific chord wins. With only Ctrl+Z bound, Ctrl+Shift+Z still fires it as before. wordproc matched Ctrl/Shift/Alt exactly by hand to avoid this. Covered by `input_chord_specificity_test`; example `examples/catalog/plugins/chord_specificity`.
- **`graphics_common.h` builds under `-Werror=pedantic`.** The backend concepts spelled placeholder arguments as C compound literals (`(const char *){}`, six sites). GCC rejects these as ISO C++ under `-Wpedantic`, which broke pumpkin-beachball's mingw64 build, and clang warns (`-Wc99-extensions`). They're `std::declval<const char *>()` now, which is what the same file already used for the other arguments. Covered by `graphics_concepts_pedantic_test`; `examples/catalog/utility/strict_pedantic_build`.
- **`set_default_font` reaches the last two places that ignored it.** The input debug overlay drew with `raylib::DrawText`, and the raylib `load_font_*` error paths returned `GetFontDefault()`, so both still showed raylib's tiny pixel font after an app set its own (cartographer). They now use `draw_text` and `get_default_font()`. The default-font API moved from `drawing_helpers.h` to `font_helper.h`, which `drawing_helpers.h` includes, so callers are unchanged. Covered by `default_font_test`.
- **Clang with the MSVC standard library compiles again.** `core/system.h` included `<cxxabi.h>` whenever `__clang__` was defined, but MSVC's STL has no such header, so clangd and direct `clang++` builds targeting MSVC died at the include (pumpkin-beachball). It's now included only when `__has_include(<cxxabi.h>)` finds it; demangling still works with GCC, libc++ and MinGW, and system names fall back to the mangled spelling elsewhere. `crash_handler.h` included `<cxxabi.h>` without using it; that include is gone. Covered in `system_profile_test`; `examples/catalog/core/system_names`.
- **The NONE backend estimates text width instead of returning zero.** Without `set_measure_text_fn`, `measure_text` returned `{0,0}`, so every "does it fit" check passed and headless centering and right alignment were computed from zero widths (pumpkin-beachball). It now returns raylib's headless estimate (`strlen * size * 0.5`, height `size`) and warns once. An installed measure fn still wins. Headless layout that sized text to zero now gets a width. Covered by `none_measure_test`.
- **`translation.h` includes `<cstdlib>` before fmt.** fmt 11.2's `format.h` calls `malloc` / `free` without including `<cstdlib>`, so a file whose first include is `translation.h` depended on some other header to declare them. endless-dance-chaos and mailboy hit `malloc` undeclared on clang 21.
- **`with_letter_spacing(0)` now clears inherited spacing.** `ComponentConfig::letter_spacing` is `std::optional<float>` (unset by default), merged on `has_value` like `roundness`, so an explicit zero overrides a base config's spacing instead of being treated as "not set". `HasLabel::letter_spacing` stays a plain `float`; code reading `config.letter_spacing` directly is a compile error — use `value_or(0.f)`. Covered by `letter_spacing_zero_test`.
- **`load_cjk_fonts` loads 4-byte UTF-8 glyphs.** Its hand decoder handled only 1–3-byte sequences, so emoji and CJK Ext-B codepoints in Korean/Japanese translations were skipped byte by byte and never reached the font. It decodes with the shared 4-byte-aware `text_units_detail::decode` now; valid 1–3-byte input, stray continuation bytes and truncated tails behave as before. Covered by `translation_test`; see `examples/catalog/plugins/translation_4byte`.
- **`SKIP_ENTITY_QUERY_MODIFICATIONS` builds again.** The direct-lambda `whereID` calls `seed_from_id`, but that helper was only defined in the default branch, so any build with the macro failed to compile (`safety/benchmarks` among them). It is shared by both branches now. Covered by `query_skip_mods_test`.
- **The mouse wheel hit-tests a scroll view where it is drawn, and Shift+wheel scrolls horizontally.** `HandleScrollInput` tested the pointer against the raw layout rect. A scroll view inside a scrolled parent ignored the wheel over its visible rows and took it over space the parent had clipped away. It uses the same scroll-and-clip hit rect as clicks now. With Shift held, a vertical-only wheel delta scrolls horizontally, so tab strips work with an ordinary mouse. floatinghotel swapped out the framework system to get the first fix; hanabi had no workaround for the second. Covered by `wheel_input_test`; example `examples/catalog/ui/wheel_input`.
- **sokol's `get_frame_time()` is the time since the last frame that ran.** It returned `sapp_frame_duration()`, one display interval, even when the target-fps gate or on-demand mode had skipped callbacks. So at target 60 on a 120Hz display everything ran at half speed, and a hanabi toast idling at 10fps lasted about a minute instead of ten seconds. It is wall time between admitted frames now, like raylib's `GetFrameTime`, and uncapped like raylib's: clamp it in the host if a long resume should not finish an animation in one step. Headless still steps 1/60. Covered by `sokol_frame_dt_test`.
- **`files::write_string_atomic` survives power loss and competing writers.** Every write used the same `<target>.afh-tmp` and never synced, so two writers to one file truncated each other's temp and a power cut could leave an empty file. Each write now gets its own `<target>.<pid>.<n>.afh-tmp`, syncs it (`F_FULLFSYNC` on macOS, `_commit` on Windows), renames it over the target (`MoveFileExW` with write-through on Windows), then syncs the directory. Whichever rename lands last wins, and a reader sees either the old file or a whole new one. The signature is unchanged. A save now waits on the disk, which can take tens of milliseconds on macOS. A replaced file keeps its permission bits, so a 0600 file stays 0600. A temp left by a crash is no longer reused by the next write. `sweep_temp_files` still removes it, but on macOS and Linux it now skips a temp whose writer process is still running. Covered by `files_atomic_write_test`: 8 threads writing one file, a reader that must never see a partial file, and a disk-full failure that has to leave the original alone and remove its temp.
- **Metal screenshots no longer leak a staging texture per capture.** `metal_read_image_pixels` kept the `newTextureWithDescriptor:` staging texture from the MSAA-resolve / private-to-shared copy paths alive forever, so every screenshot leaked one full-size texture. It is released after `getBytes:` (and on the allocation-failure path) when built without ARC. Covered by `staging_texture_leak_test`, which captures 200 frames and bounds resident growth.
- **Particle drag no longer flips velocity at low frame rates.** `particles::Emitter::update` applied drag as `vel -= vel * drag * dt`, which reverses velocity when `drag * dt > 1` (reachable at the 0.1s dt clamp with drag above 10) and decays by a different amount per frame rate. Drag is now the exact `vel *= exp(-drag * dt)`, so velocity after a given elapsed time matches at any step size and never changes sign. At 60fps the decay is within a few percent of the old step for typical drag values. Covered by `particles_test`.
- **Scroll easing snaps under instant motion.** `HasScrollView::ease_scroll` honoured `scroll_smoothing` but never `motion::is_instant()`, so a smoothed view kept gliding when the app (or reduced-motion seeding) had asked for instant motion. It snaps `scroll_offset` to `scroll_target` on the same frame now, like `modal`'s enter/exit paths; with instant off the glide is unchanged. The instant flag moved to `src/plugins/animation/instant.h` so the UI leaf can read it without pulling in `Track`. Covered by `scroll_smoothing_test`.
- **Scheduled toasts fade again.** `toast::schedule` never added `HasOpacity`, so `ToastLayoutSystem`'s fade write was guarded away and every toast stayed fully opaque until it vanished. Scheduling adds `HasOpacity` at full opacity now, and the layout pass eases it to zero over the toast's lifetime. Covered by `scheduled_toast_fades_over_its_lifetime` in `toast_test`.
- **Sokol `run()` honours `RunConfig::display = DisplayMode::Headless`.** It always entered `sapp_run` and opened a window, so wordproc drove its headless mode by hand with `graphics::init(Config{Headless})`, its own frame loop and an explicit shutdown. Headless `run()` now creates the offscreen device, calls `init`, then `frame` until `request_quit()`, then `cleanup`, and shuts the device down, the same lifecycle raylib's headless `run()` already had. `request_quit()` works without a window. Windowed runs are unchanged. Covered by `sokol_headless_run_test`; `examples/catalog/utility/sokol_headless_run`.
- **`Library::load` no longer leaks a duplicate.** It converted the file (loaded the texture, model, sound) before `add` noticed the name was taken, then dropped the result without `unload`. It checks the name first now and warns. Covered by `library_duplicate_test`.
- **A system that overrides only the const `should_run` is gated again.** `SystemManager` calls the non-const overload, and the base version returned `true`, so a const-only override was never consulted and the system ran every frame with no warning (cartographer hit it twice, in render systems that drew when they shouldn't). The base non-const `should_run` forwards to the const one now, so overriding either works; a non-const override behaves as before. Covered by `should_run_overload_test`.
- **`draw_model` draws again after `draw_model_instanced` of the same model.** raylib's `DrawMeshInstanced` leaves the four instance-matrix attributes enabled on the mesh's vertex array, pointing at the buffer it has just deleted, and the next plain draw of that model came out blank. `draw_model_instanced` now turns them off after each mesh. Only seen when one model is drawn both ways in a frame, e.g. `model_stress` switching modes, or instanced copies far away with a few drawn singly up close. Covered in `models_test`.
- **A nested menu or popover no longer flashes a parent offset away on its first open.** The panel's screen placement is converted through its zero-size holder's rect, but the holder was only built while open, so on the first open its rect was still the pre-layout default and the panel landed offset by its parent for one frame before snapping back. The holder is built while closed now, so its rect is laid out before anything hangs off it. Pinned by `popover_nested_first_frame_anchors_to_screen` in `menu_test`.
- **Fonts load the glyphs a UI actually types.** `load_font_from_file` asked raylib for its default set, which is 95 ASCII glyphs, so an arrow, chevron, checkmark or ellipsis drew nothing at all: no box, no warning. Latin-1, punctuation, arrows, box drawing, shapes and check marks are loaded now (`default_codepoints()`), and `font_has_glyph(font, cp)` answers whether a face covers something.
- **A full font atlas says so.** fontstash raises `FONS_ATLAS_FULL`, nothing registered the callback, and the default handler is null, so a dropped glyph took its advance with it and `measure_text` quietly returned short or zero. Every wrap, hug and ellipsize is computed from that, making a full atlas silent layout corruption. It warns once now and names the size. `AFTERHOURS_FONT_ATLAS_SIZE` raises the 2048 default, which was hardcoded.
- **Sokol's GPU pools are sizeable.** They were left at sokol's defaults, and exhausting one asserts inside sokol rather than returning an error, so a consumer could not size its way out of a crash it could not see coming. `AFTERHOURS_SG_PIPELINE_POOL_SIZE`, `_IMAGE_`, `_BUFFER_` set them, applied at both the windowed and headless setup so they cannot drift.
- **A headless resize no longer leaks Metal pipelines.** `load_render_texture` made a new sgl context each time, and `sgl_destroy_context` does not release the five render pipelines the context created. The context depends on the pixel formats and sample count, never the size, so it is keyed and reused now. Measured in hanabi's resize soak: RSS growth over 1000 frames goes from +5104 KB (2.5x over its budget) to +160 KB, live blocks at frame 2000 from 149,560 to 17,989.
- **`has_child_of` / `get_with_child` stop dynamic_casting empty slots.** They walked all 128 component slots per call, RTTI-checking the ~120 that hold nothing. They consult `componentSet` first now: 96,712 dynamic_casts a frame becomes 5,364 on wm's heaviest screen, an 18x cut, with no behaviour change.
- **Text is measured once, not once per frame.** The render path walked every label glyph by glyph every frame, for text that had not changed: measured on wm, 995 measurements a frame on one screen resolving to 101 distinct questions, and across frames all of them repeats. A memo at the backend's `measure_text` (`measure_memo.h`) takes that to 101 real measurements for the life of the process, a 99.8% hit rate, with no call site changed. Keyed on text, size, spacing and the font's own identity, so a reloaded atlas or a different face is a different entry; `measure_memo::clear()` if you swap a face under a live handle.
- **`imm::mk()` no longer allocates.** It built a `std::stringstream`, streamed the file path and function name into it, materialised a `std::string` and hashed that, once per widget per frame. The same bytes are hashed in place now: 3 allocations per call becomes 0, so a 500 widget frame stops paying 1500 allocations and 108 KB to answer a question that is pure lookup. Hash values differ from before, which matters to nothing: the map is rebuilt every process.
- **`whereID` stops scanning.** It compared every entity's id against the target even though the collection answers that in O(1) through `id_to_slot`, so the most obvious spelling of the most common lookup was the slowest one. It seeds the query's candidate set now: 1 filter evaluation instead of 1000 on a 1000-entity collection, same allocation count. The filter stays in place, so ordering and every other mod are unchanged, and a query built from a bare vector or with entities still in temp falls back to the scan.
- **`virtual_list` culls for real.** Rows are recycled by slot so a 10k list holds ~30 entities instead of one per row ever scrolled past, the un-built rows count toward the scroll range so the bar spans the whole list, the window covers where the view is easing to so a fling does not flash blank, and the first frame sizes itself from the container instead of guessing 60. A press whose row scrolls out from under it is cancelled rather than firing on the row that replaced it. No API change.

- **Clicking a placeholder field and typing aborted the process.** Click-to-position measured against `HasLabel`, which holds the *placeholder* when the field is empty, so the first keystroke inserted past the end of an empty string — `std::out_of_range`, `SIGABRT`. `with_placeholder` is safe to adopt now.
- **`text_area` honours `with_readonly()` and `with_disabled()`.** It copied only the copy/cut/paste flags from `ComponentConfig`, so a readonly or disabled area stayed editable and focusable. It wires `text_readonly`/`disabled` like `text_input` now: readonly still focuses, selects and copies but rejects typing, Enter, and every delete; disabled does not focus, dims to half opacity, and ignores clicks, drags and wheel. Covered in `text_area_test`.
- **A scroll view no longer squashes its content to fit.** `solve_violations` never exempted scroll views, where overflowing is the point, so a list longer than its viewport had every row shrunk toward zero. Latent until `48f808d` made the solver recurse into absolute subtrees. If you pinned strictness to 1 to stop this, you can stop.
- **A horizontally-scrolling column no longer over-reports content width.** `MeasureScrollViews` read the scroll flags rather than `flex_direction`, so a `vstack` scrolled on X — every table — summed its rows' widths instead of taking the max, and scrolled N times too far. Remove any fudge factor on `content_size.x`.
- **Headless runs degrade instead of collapsing** (no effect if your headless mode still makes a GL context): resolution falls back to `window_manager::headless_resolution` instead of (0,0), `measure_text` estimates from font size instead of returning {0,0}, and new `afterhours::shutdown()` deletes entities before the backend — leaving both to static destruction threw `std::bad_variant_access`. Each warns once.
- **`SINGLETON_FWD` still does not work in class scope** — use `SINGLETON_CLASS_FWD`, which has existed since `e9c662b`. Comment-only change.
- **A headless resize requested mid-pass waits for the next frame** (hanabi #374). `set_window_size` during an active pass used to tear down the render target under the pass and abort in sokol's validation. The request is parked now and applied between frames; repeats coalesce, invalid sizes are ignored, and asking for the current size cancels the pending change. Windowed resizes never recreated GPU resources and are unchanged. `sokol_resize_test` drives a mid-pass request, a texture-mode request and 64 repeat resizes.
- **A focused field's ring is no longer clipped by the field's own clip** (hanabi #375). A field clips its contents (`HasClipChildren`), and the focus ring resolved its scissor from a clip whose first term is the element's own rect, so the ring's outward strokes were cut on every side and the top went first in a form. The ring resolves ancestor clips only now; a field inside a scroll view is still clipped by the viewport. The app-side wrapper hanabi kept for this (`edged_field.h`) can go.
- **Sokol `draw_circle_v` keeps its fractional centre** (hanabi #78). It truncated the centre to int on the way to the integer overload, so a circle at (20.9, 20.9) drew at (20, 20); the raylib backend never did this. The fill takes floats now and both overloads share it. Pinned by pixel centroid in `sokol_geometry_test`.
- **`RoundedCorners` names the corner it rounds** (hanabi #81). The enum called bit 0 `TOP_LEFT`; both backends read bit 3 as top-left, and every UI bitset reaches them unchanged, so `top_left(ROUND)` rounded the bottom-right. The enum matches the backend layout now. If you used the named API and compensated for the flip by hand, your corners swap back; raw bitsets are unaffected.
- **`begin_shader_mode` is unambiguous in UI headers again.** The four call sites in `rendering.h` / `render_primitives.h` resolved to both the backend helper and `graphics::` (via ADL on the shader type) in any translation unit that included both, which is a compile error sokol consumers with widget shaders hit. The sites are qualified to `::afterhours::`.
- **`load_font_for_string` has the headless fallback its siblings have** (kart). It returned raylib's default font where the other loaders build the atlas, which is an invalid handle without a GL context. It builds the atlas now, gated on a window existing, because the upload itself crashes with no window at all.
- **Absolute translates resolve against their own axis** (kart). `apply_modifiers` resolved both x and y against the screen height, so a `w1280()` x-offset was scaled by the height at any non-square resolution. Each axis resolves against its own dimension now; flow translates share the path and are corrected with it.
- **A labelled checkbox's toggle fits its row** (kart). The toggle is a button, so its height came from the label plus theme button padding and overflowed the row's height intent, which is the layout warning kart reported. `checkbox()` pins the toggle height to the intent now.
- **Font textures carry mipmaps with trilinear filtering.** A label rasterised large and drawn small shimmered and broke up, because the atlas texture was minified with plain bilinear and no mip chain. Atlases generate mipmaps on load now.
- **An open dropdown tray stays on screen at the right edge.** `overlay::place` already clamped both axes, but the tray only applied the Y correction, so a dropdown near the right edge ran off screen (wordproc). The tray now translates by `placed.x - anchor.x` as well. Covered by `d13_dropdown_tray_clamps_at_right_edge` in `downstream_gaps_test`.
- **`imm::pagination` Previous skipped a page and its page buttons selected the next page.** Previous handed `prev_index` an already-decremented index, so it stepped two pages back (wrapping only by accident at the first page), and each numbered button passed `i + 1` where a zero-based page index was expected, so button *N* selected page *N + 1* and the last button wrapped to the first. Both pass the plain index now, and the click focus lands on the button for the selected page. Covered by `pagination_test`.

### e2e
- **An app command registered before the built-ins now wins, and one registered after warns.** The runner merged a newly dispatched command only after the first update system had run, so whatever was registered first missed it on its first frame and a later built-in consumed it. `register_before_builtins` therefore never actually overrode anything. The runner merges right after dispatch now. A `register_command` handler that finds its command already consumed logs once: `'disable_animations' was consumed by a handler that runs before the register_command for it`. kart-afterhours lost its own `disable_animations` this way and nothing said so. Covered in `e2e_register_command_test`.
- **`register_command(sm, name, fn)`** registers a game command as a lambda that sees only unconsumed commands with that name, and **`register_command<Args...>(sm, name, fn(cmd, Args...))`** also parses the arguments: the wrong count fails with `set_score takes 2 arguments, got 1`, an unparseable one with `set_score: cannot parse argument 2 'abc'`, and `fn` is not called. **`PendingE2ECommand::expect(ok, mismatch)`** consumes or retries with the mismatch. pumpkin-beachball's 719-line command file was this shape repeated with `maybe_arg_as` and a usage check per command. Covered by `e2e_register_command_test`.
- **`type` queues Unicode codepoints, not UTF-8 bytes.** `type café` used to queue the signed bytes of `é` as two negative chars, so `get_char_pressed` never returned 0xE9 and the text arrived as `caf`. `test_input::push_text(utf8)` decodes once and `KeyPress::char_value` / `push_char` take an `int` codepoint. Text that is not valid UTF-8 fails the `type` command and queues nothing. Covered by `e2e_type_command_test`.
- **`dump_ui` shows resolved spacing**: `padding="t r b l"`, `margin="t r b l"` and `gap="n"` in pixels, written only when non-zero, so existing dumps of unspaced nodes are unchanged. A spacing audit can now tell a nested inset from a layout error without an app-side JSON sidecar (floatinghotel). Covered in `dump_ui_test`.
- **A screenshot that fails to capture fails the script.** `set_screenshot_callback` and `HandleScreenshotCommand` take a callback returning `bool`; `false` fails the command with `screenshot 'menu' failed to capture`. A `void` callback still works and always passes. pumpkin-beachball's NONE stage logged a failed capture for every screenshot and still reported 12/12 PASS. Covered by `e2e_screenshot_test`.
- **`testing::is_e2e_running()`** (`e2e_testing/test_input.h`) is true once an `E2ERunner` has loaded a script or a script directory. Use it to keep wall-clock readouts such as FPS and real clocks out of e2e screenshots. pumpkin-beachball's FPS counter read 1446, 723 and 187 across screenshots of one deterministic run, and the only test flag was the input plumbing's `test_mode`. Covered by `e2e_is_running_test`.
- **`register_unknown_handler(sm, {"spawn_enemy", ...})`** names commands another state handles. Those wait (retry) instead of failing on the first frame, so the unknown handler can sit in a pack shared by every state's manager. A listed command no state takes times out after the usual 30 frames with `'spawn_enemy' waited for a state that handles it`; wrap it in `wait_until` for a longer load. Other unknown commands still fail at once. Cartographer kept the unknown handler out of its shared pack because of this. Also on this branch: the runner merges a dispatched command straight away, so the first update system sees it on its first frame (same one-line change as gap/e2e-shadowed-command). Covered by `e2e_defer_unknown_test`.
- **Results you can read without the log.** `E2ERunner::results()` returns one `ScriptResult` per script, including a single-script run (now with `timed_out`). `write_results_json(path)` writes them with run/passed/failed counts, `success` and a final `"complete": true`, through a temp file and a rename so a crash never leaves half a file. `--results-json PATH` (via `configure_runner`) makes `print_results()` write it. A single-script run now prints `[PASS] name` / `[FAIL] name (N errors)` like batch mode. An empty script directory or an unreadable script fails at load time and finishes the runner: before, the first was an all-green zero-script run and the second never finished. Covered by `e2e_results_test`.
- **`hold_key KEY` / `release_key KEY`** keep any key down, modifiers included (`hold_key CTRL`, `hold_key CMD`), until released or the script ends. `key` taps for two frames and releases its own modifiers, so it could not hold Ctrl across several Tab presses. Unknown key names fail at once. floatinghotel's recent-tab switcher and pong's held paddle wrote this themselves. Same commit as on the `pong-gaps` branch. Covered in `e2e_key_command_test`.
- **`graphics::is_key_pressed` and its siblings see injected keys** (hanabi, floatinghotel). Under `AFTER_HOURS_ENABLE_E2E_TESTING`, `is_key_pressed`, `is_key_pressed_repeat`, `is_key_down` and `is_key_released` in `graphics.h` go through `test_input` like the input plugin does, so a shortcut read from the graphics layer fires for `key` in a script instead of only asking the hardware. `is_key_released` is new in `test_input` and gets a release edge from `input_injector::set_key_up`, one frame after the press. Covered by `graphics_key_injection_test`.
- **`expect_terminal_*` commands for the terminal console** (`e2e_testing/terminal_commands.h`): `terminal_commands::register_terminal_commands(sm, console, is_open)` (or pass an `Overlay&`) registers `expect_terminal_open`, `expect_terminal_closed`, `expect_terminal_input <text>` and `expect_terminal_output_contains <text>`, asserting on the public `Console::input` / `Console::output()` and the overlay open state instead of each game hand-rolling them. Covered by `terminal_commands_test`; see `examples/catalog/plugins/terminal_commands`.
- **Gestures on a named element:** `mouse_down_ui NAME [dx dy]` presses and holds, `mouse_move_ui NAME [dx dy]` moves (a hover, or the middle of a drag), and `scroll_wheel_ui NAME dx dy` moves onto the element and scrolls. Offsets are from the element's top left, as for `double_click_ui`, and omitted means the centre. A drag is `mouse_down_ui a` / `mouse_move_ui b` / `mouse_up`, so a script can assert while the button is still held. hanabi's minimap drag was written in absolute window coordinates because only clicks took a name. Covered by `e2e_ui_gestures_test`.
- **`register_shared_handlers(state_sm, pack)`** runs one pack of e2e handlers from several SystemManagers. Fill a `SystemManager pack` with the usual `register_*` calls (custom handlers, then `register_unknown_handler`, then `register_cleanup`) and call this on each state's manager; whichever manager ticks runs the pack once. A command handled in every state is registered once, and `register_unknown_handler` works again with several managers, because the one pack sees every command. Covered by `shared_handlers_test`.
- **`wait_until SECONDS cmd args...`** retries `cmd` every frame until it passes, failing only when SECONDS run out, with the last failure as the error (`wait_until 2s: rope is Holding, expected Measuring`). The inner command is parsed by its own rules, so `wait_until 3 expect_text Saved game` keeps its rest-of-line argument. A failure (`fail()`) or a stall past the 30-frame timeout is rearmed (`PendingE2ECommand::rearm()`) instead of reported, so a game handler that fails on the first wrong frame works unchanged. Check-only: a command with side effects (`press_key`, `teleport_player`) runs again on every retry. It counts against the per-script timeout. Covered in `e2e_retry_test` and `e2e_arguments_test`.
- **`wait_wall SECONDS` and `wait_until_wall SECONDS cmd args...`** wait in real time (`steady_clock`) instead of host `dt`, so a script can wait on a worker thread or subprocess whatever the tick rate or `--time-scale`. `wait` and `wait_until` are unchanged and still scale. While a wall deadline is ahead, the per-script timeout pauses and the 30-frame command timeout does not fire. An expired `wait_until_wall` fails the script with `wait_until_wall 2s: <last mismatch>`. `is_idle_waiting()` stays false during `wait_wall`. Covered in `e2e_retry_test` and `e2e_arguments_test`.
- **A timeout that nothing touched says so.** If no handler ever called `retry()` / `retry_with()` on a command, its timeout adds "nothing consumed or retried it, is its handler registered on this SystemManager?". Serial dispatch made this the usual symptom of a handler registered on only one of several managers.
- **`mouse_down` / `middle_down` keep the press edge one frame**, like `click`: a system that runs before the e2e handlers used to never see an injected press (`press_frames = 0`). The edge is re-raised once only if nothing read it, and the button stays held until `mouse_up`.
- **The harness ships with the engine** (`e2e_testing/harness.h`): `E2EArgs`, `parse_e2e_args`, `should_run_e2e`, `screenshot_path`, `count_e2e_scripts`, `configure_runner`. Every consumer was writing its own ~150 line parser and they had drifted. New flags while there: `--screenshot-dir` and `--e2e-speed` (an accepted spelling of `--time-scale`).
- **`wait_frames N` waits N frames.** It stored `N/60` seconds and the runner counted that down with `dt`, so it was a frame count only if the host ticked at exactly 60Hz, and `--time-scale` changed it again. Whether a suite was reproducible was the host's undocumented decision.
- **`right_click_ui <name>` and `right_click_text "..."`** open a context menu the way the app does. A secondary click could only be aimed at a coordinate, which goes stale the moment the layout moves.

- **Assertions that passed without testing anything.** Injected `scroll_wheel` did nothing (wiped by `reset_frame` before the reader ran; now survives one reset, not drained on read, matching raylib). Injected pinch was delivered twice (now drained on read). `expect_no_text` always passed (missing from the parse chain, and treated a not-yet-rendered registry as absence). The visible-text registry ignored clip rects, so scrolled-away text still counted.
- **`expect_no_text` waits for a render**, by `VisibleTextRegistry::generation()` rather than frames — an app running several `tick()`s per render could burn the whole wait without one. Failures also name the label that matched, which is often a longer string nobody had in mind.
- **Failures are charged to the script that caused them.** A script's own `reset_test_state` doubled as the batch loader's separator and so ended the script early; the separator is now the unspellable `__end_of_script`. And a script's last command was finalized before it ran, so a failing final assertion exited 0 in single-script mode.
- **`dump_ui` is registered.** It was fully implemented and never registered, so scripts got "unknown command" — whose message blamed the consumer's registration order for a command they never had the chance to register. `register_ui_commands(sm, dump_fn)` takes the sink; without one the XML is logged.
- **A timeout names what it was about.** `Command 'assert_ui' ('no_such_widget') timed out` instead of four identical lines for four assertions, and the `expect_text` family prints the visible-text registry untruncated, one label per line, instead of the same 200 chars for every failure on a screen.
- **Injected right-clicks release.** `reset_frame` gated press-expiry on the left button, so an injected secondary press stuck down for the rest of the run and broke unrelated scripts files later.
- **`is_mouse_button_down(1)` returns injector state in test mode** instead of always `false`.
- **Commands run in script order now.** The runner dispatched one command per frame while an earlier one was still retrying, so a retrying assertion kept sampling while the script moved on — it could pass against a later state, or report that state's value on timeout (an overview assert reported the Vertical tab's geometry). Dispatch waits for the pending command to resolve; every pending command is bounded by the cleanup timeout, so this cannot stall. Pinned by `serial_dispatch_waits_for_pending_command` in `e2e_arguments_test`.
- **Clicks land on the visible part of a clipped element.** `click_ui` / `click_text` aimed at the centre of the element's full rect, which for a partially-clipped element can sit outside its hit area or off-screen — a click on the last option of a scrolled dropdown missed and closed the dropdown without selecting. They aim at the centre of the clipped rect now; a fully-clipped element has no click target and fails instead of clicking an invisible point. Pinned by `click_ui_clicks_the_visible_centre_of_a_clipped_element` in `e2e_arguments_test`.

*Re-run your suite and read the new failures before silencing them.* Two of ours were real: a script that resized to 1080p and never resized back, and an assertion on a row that had never been on screen.

### Two silent fallbacks now warn

Same behaviour, they just say so; expect a burst on first run. `with_font_weight` needs a `"<font>@bold"` variant and falls back to the base font without one (this is why it gets filed as "no font weight support"), and `TextOverflow::Wrap` does nothing unless a font size is pinned.
- **Profiling that cannot collect, and a perf provider being replaced, warn once.** `builtin_profile::enable()` ignored `Collector::start()` returning false when built without `AFTERHOURS_ENABLE_PROFILING`, so `dump_profile` reported an empty profile with no reason; it warns once now and still installs the provider. `perf_commands::set_provider` replacing a provider that already has callbacks warns once; the new provider still takes effect. Covered by `perf_provider_warn_test`.

### Already works, despite the gap docs

The resolved layout tree is walkable (hanabi #74): `UIComponent::children` is emptied only at the start of the UI update, so a system registered after `register_after_ui_updates` (or after `ui::setup`), or any render system, sees this frame's full tree with laid-out rects. It is the app's UI-building systems, between the two, that see a tree still being rebuilt. Pinned in `setup_test`. Don't rebuild: styled spans wrap (hanabi #22), `\n` is a hard break (#24), ellipsis + `expand()` doesn't hang, `with_styled_label` gives multi-colour text, `with_font_tier` is deprecated for `with_font_size(FontSize::Small)`.

### Docs
- **Minimal consumer builds** (`examples/catalog/builds/`): `pure_ecs` (none backend, no display), `logic_only_ui` (input, UI and layout against a supplied resolution, no display) and `offscreen_render` (raylib headless GL context, writes a PNG), each the smallest makefile that works. The README there says which one a test suite wants, what each needs installed, and when to merge new entities before the first frame. MyNameChef had to assemble these combinations itself.

`FlexWrap`'s comment claimed `Wrap` was the default. It is not — `UIComponent` and `ComponentConfig` both start at `NoWrap`, as do 3860 of 3863 nodes in a downstream sweep.

**Resizing, scaling, pillarbox / letterbox** (`docs/letterboxing.md`, linked from the README): the window manager already owned this — `window_manager::content_viewport` (dest + scale), `window_to_content` / `content_to_window`, and `get_mouse_position` already applying the mapping — and pong was re-deriving the present math. The guide documents the content/window model, the present snippet, input mapping, and the fixed non-16:9 opt-out (skip `CollectCurrentResolution`, set `ProvidesCurrentResolution` yourself). No API change.
